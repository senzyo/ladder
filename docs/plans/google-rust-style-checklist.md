# Google Rust Style Guide 逐条对照

来源：[规范原文](https://google.github.io/styleguide/rustguide.html)，读取日期：2026-10-23。执行范围以[重构方案](google-rust-style-refactor.md)和用户确认的决策为准。

本表用于依赖维护通过后的重构阶段；前置依赖升级、交接状态及批次证据见[实施交接](dependency-upgrade-and-refactor-handoff.md)。

本表按规范的实质条款逐项映射。状态含义：**调整**为计划中的修改；**保持**为初审已满足、实施后复核；**条件适用**为根据条款自身范围或例外保留现状；**不适用**为专属代码库要求。本表保留初审分类，不是最终验收报告。

2026-10-25 进度：依赖维护及 R1–R5 完成；导入与 expect 上下文、平铺职责模块、具名内部结果、FnOnce 状态访问及按资源划分的故障策略已落实，Clippy、84 项测试及双架构构建通过；R6–R7 待做。typed COM 迁移因 HRESULT 契约差异已由用户明确延期，保留手写接口，不能将该项标为通过。详见实施交接；最终收口时逐行补充实际差异或例外依据。

已落实的条目：100 列 rustfmt、主要术语/try_new/spawn_background 名称、导入范围与限定、expect 上下文、main 的声明/装配边界、平铺职责模块及原测试迁移。R4 补齐 release/下载资产/设置解析/菜单的具名结果，私有全局状态和 FnOnce 闭包访问、资源守卫与必要查询的 must_use、Download derive Default、菜单禁用枚举、复杂循环头提取和风险断言/契约文档；展开释放测试使用工作线程，不再调用 catch_unwind 或替换全局 panic 钩子。R5 删除全部四处中毒内部值恢复：应用状态释放锁后清理退出、日志固定 IO 错误、警告缓存固定降级提示；普通 panic 与状态中毒共用全链无 tracing 清理，以局部锁和带超时的独立子进程/记录替身验证。测试 hook 的替换仅发生在独立子进程中。unsafe 契约留待 R6；数值字面量/宏 matcher 等格式细项仍需最终逐项核验。本表初审分类保留，已完成部分也须在 R7 复核。

## 适用原则与代码组织

| 规则 | 初审状态 | 落地方式或理由 |
| --- | --- | --- |
| 规范适用范围与目标 | 保持 | 主动采用通用规则，以可读性、维护性和可检查性为目标 |
| 遵守公开 Rust 风格 | 调整 | 继续使用 rustfmt、Clippy，按本清单处理命名与 API |
| 按应用/库上下文应用 API 规则 | 条件适用 | 本项目是桌面应用，不为不存在的库消费者引入抽象 |
| 优先小 crate | 不适用 | Chromium 专属；已确认保留单 Cargo crate |
| rust_library 平铺文件布局 | 不适用 | 不套用 Chromium 构建布局；本项目采用平铺叶模块是自身的组织方案 |
| 叶模块按主要自定义类型命名 | 调整 | `app_error`、`app_state`、`com_guard` 等按主要类型命名；无单一主要类型的模块按功能命名 |
| 非叶模块不实现大量 API | 调整 | `main.rs` 仅保留声明和少量装配，业务实现进入叶模块 |
| 避免 glob import | 调整 | tracing prelude 改为实际使用的 trait；保留明确允许的内联测试 `use super::*` |
| 一条 use 只导入同一模块中的项 | 保持 | 保持现有导入粒度，迁移时不引入跨层嵌套花括号 |
| trait 尽量在局部导入 | 调整 | 单个函数使用的 Digest、Read、格式化 Write 及 Windows 扩展 trait 下移 |
| 跨模块顶层函数带模块限定 | 调整 | 普通 Rust 函数采用模块限定；名称明确的 Win32 函数按原条款例外保留直接导入 |
| 类型导入后不带模块限定 | 调整 | 清理完整类型路径；`io::Error` 等有歧义的名称保留模块限定 |
| 使用合适的导入机制 | 不适用 | Chromium 专属，不引入 chromium 导入宏 |

## 格式、所有权与函数接口

| 规则 | 初审状态 | 落地方式或理由 |
| --- | --- | --- |
| 使用对应格式化工具 | 调整 | 行宽 100，保持 edition 2024；逐项核对十六进制小写、宏 matcher 格式和不可见字符转义，stable 不支持的选项按原规范允许的例外记录 |
| 退出自动格式化的条件 | 保持 | 当前无 rustfmt skip，不为个人排版偏好新增 |
| 避免不必要的 Rc/Arc | 条件适用 | 日志 writer 需共享多线程写入，保留 Arc；不为了去掉 Arc 增加复杂所有权模型 |
| 借用优于深拷贝 | 调整 | 审查 release 资产过早 clone；释放状态锁和跨线程所需的快照复制保持 |
| 不可变数据使用灵活引用 | 保持 | 继续使用现有 `&str`、`&Path` 和切片，不批量泛型化 |
| 返回迭代器或拥有的集合 | 条件适用 | 排序去重的配置、警告和 PID 列表自然形成集合，保留；不为局部流程增加生命周期负担 |
| 参数采用迭代器或切片 | 条件适用 | 已知应用调用者使用切片足够，不预设外部库需求 |
| 使用 Into 参数的条件 | 保持 | 没有泛滥的 Into 参数，已有 AsRef 命令入口按实际需求保留 |
| enum 优于含糊的 bool 参数 | 调整 | 审查菜单禁用等自有接口；目的清楚的局部表达式及 Win32 原始签名保持 |
| 选择 Option、Result 或 panic 报错 | 调整 | 一般错误契约保持；中毒处理和 panic 清理按已确认的新策略执行 |
| newtype 与类型别名 | 保持 | 函数签名别名保持，避免为所有字符串或路径新增包装 |
| 具名字段优于多字段元组 | 调整 | release、URL/hash、设置解析和跨函数菜单结果具名化；小范围测试样本元组保持 |

## trait、并发与宏

| 规则 | 初审状态 | 落地方式或理由 |
| --- | --- | --- |
| 按需要增加 trait 实现 | 保持 | 新 trait/derive 需有具体用途，不批量扩大接口 |
| 标准 trait 优于同义自定义方法 | 保持 | 继续使用 Error、Write、Default 等已有实现 |
| 能 derive 则优先 derive | 调整 | `Download::default` 改为 derive；包含特殊默认值的实现保留 |
| 泛型与 dyn Trait 的选择 | 条件适用 | 当前无需要替换的 dyn 接口，不为应用重新设计泛型框架 |
| trait 与固有 impl 的边界 | 保持 | 不用 trait 单纯组织代码 |
| 扩展 trait 的使用 | 保持 | 当前没有自定义外部类型扩展接口，不为本次整理新增 |
| Copy/Clone/Default/比较等重要 trait | 条件适用 | 资源类型不强加 Clone；包含 String/I/O Error 的错误不强加 Copy；新增实现须满足真实契约 |
| 主要 From 转换配显式构造器 | 条件适用 | AppError 的 From 服务于 `?`，已有具名变体；无需无消费者的重复工厂 |
| 选项集合实现 Default | 保持 | 设置集合已有默认值；必填下载地址不虚构空默认 |
| 禁止继续使用中毒锁内部值 | 调整 | 删除四处内部值恢复，按应用状态/日志/警告分别处理；不清除中毒标记 |
| 不使用 async/await | 不适用 | Chromium 专属，本次也不引入异步运行时 |
| 不通过标准库启动线程 | 不适用 | Chromium 专属，保留后台线程模型 |
| 使用 fuchsia_sync::Mutex | 不适用 | Fuchsia 专属，保留标准库 Mutex |
| 宏的使用 | 保持 | 保留日志、格式化、derive 等成熟宏，不引入自定义元编程框架 |

## 命名、文档与其他语言特性

| 规则 | 初审状态 | 落地方式或理由 |
| --- | --- | --- |
| 方法命名 | 调整 | 类型/查询名称对齐领域术语；HTTP GET 等方法不误改为字段 getter |
| 生命周期命名 | 保持 | 现有局部关系与 static 用途清楚；新增接口再按语义命名 |
| 泛型参数命名 | 保持 | 闭包 F、订阅器 S 等结合上下文使用，不为改字母制造差异 |
| 扩展 trait 命名 | 保持 | 当前无自定义扩展 trait；将来需要时使用 Ext 后缀 |
| 初始化函数命名 | 调整 | `ComGuard::new() -> Result` 改为 `try_new`；获取锁和启动流程不机械改成构造器 |
| 避免缩写 | 调整 | `spawn_bg` 等使用完整词；DNS、COM、PID、URL 及 ABI 名称保持 |
| 文档编写时机、形式和契约 | 调整 | 补关键公开接口、panic/unsafe 前提及模块职责；不复述自解释名称 |
| unsafe 的必要性、封装与说明 | 调整 | 缩小 FFI 边界、补 SAFETY 与技术理由，优先 typed COM；有调用者义务的边界保留 unsafe |
| 禁止不稳定功能 | 保持 | 保持 stable，不增加 feature gate 或 nightly 要求 |
| getter/setter 命名 | 调整 | 保留 take_child/set_child 等正确名称；修正状态访问语义 |
| 接受闭包的访问器 | 调整 | 已确认 with_app_state/with_mut_app_state；保留设置保存的现有串行锁范围 |
| 成套实现预期 API | 保持 | 无自有 len 却缺 is_empty 的容器接口，不凭空增加方法 |
| 不调用外部 doc(hidden) 项 | 保持 | 当前未见刻意调用隐藏 API；COM 迁移仅使用公开绑定 |
| 谨慎使用 const fn | 保持 | 不为推测的性能收益增加 public const fn |
| 不滥用非数学运算符重载 | 保持 | 无此类自定义运算符接口 |
| 对外 enum 的 non_exhaustive | 条件适用 | 单 binary 内部类型没有跨团队公共 API 消费者，不机械标注 |
| 对外公开字段 struct 的 non_exhaustive | 条件适用 | 内部设置与结果类型同样不属于该公共库场景 |
| 函数 must_use | 调整 | 审查纯查询、路径计算和重要返回值；已有 Result 等保障的函数不重复标注 |
| 类型 must_use | 调整 | 重点审查原子守卫、COM/单实例守卫及不能直接丢弃的结果 |
| 不在 main 前执行运行期代码 | 保持 | 静态常量/OnceLock 初始化不引入运行期构造器；build.rs 是构建脚本 |

## 实现与测试

| 规则 | 初审状态 | 落地方式或理由 |
| --- | --- | --- |
| 不过度使用类型推断 | 调整 | 复杂 collect 和跨模块结果保留必要类型信息；显然的局部推断保持 |
| 模式匹配优于检查后 unwrap | 保持 | 现有 match/if let/let else 为主；实施时复核新增调用点 |
| expect 优于 unwrap | 调整 | 构建脚本及测试准备补不变量说明；合理 fallback 的 unwrap_or 家族不机械替换 |
| non_exhaustive 匹配不省略已知分支 | 保持 | 复核第三方枚举匹配；仅关注特定情况的模式按原条款例外处理 |
| 断言提供上下文 | 调整 | 为不直观条件补原因或相关值，自解释 assert_eq 不增加重复句 |
| 直接循环优于难读组合链 | 调整 | for 头中的复杂 zip/chain/map_while 提为具名变量；简短 any/all 保持 |
| 不直接调用 catch_unwind | 调整 | 展开释放测试改用工作线程与 join；不在并行测试中替换全局 panic 钩子 |
| 拼接和模板替换优先 format/write | 保持 | 现有格式宏继续使用；XML 字符转义的 replace 不属于模板替换 |
| 使用各代码库对应测试框架 | 条件适用 | 继续 Cargo 的 #[test]；Chrome/Fuchsia 示例框架不适用于本项目 |

## 收口检查

- 每个“调整”项应映射到实际差异或说明为何按原规则例外保留；不能只写“已遵循”。
- 每个“条件适用”项保留判断理由；它们不同于自行放宽规范。
- 若发现安全封装必须同时修复独立功能缺陷，先记录依赖并暂停该项，重新讨论范围；不隐蔽混入修复。
- 完成后同时复核方案中的正常行为不变量、故障策略和验证缺口；规范清单不替代行为测试。
