# 中毒状态终止运行，紧急清理绕开应用状态与日志锁

本项目使用全局应用状态协调代理核心和 DNS；部分操作先启动核心再登记状态，因此状态锁中毒后简单返回“不可用”可能留下未登记的核心。决定不读取中毒状态，而是在释放错误携带的锁守卫后，尽力停止核心、恢复 DHCP DNS 和刷新 DNS，然后以失败状态退出；文件日志中毒仅停用文件写入，启动警告缓存中毒仅放弃旧队列，两者不单独触发退出。

普通 panic 钩子与状态中毒共用不获取应用状态锁、不经过 tracing 的紧急清理底层，避免 panic 发生在日志锁持有期间时重入同一锁。保留 release 的 `panic = "abort"`；清理是尽力尝试，不能依赖 Drop、展开或操作系统调用必然成功。正常路径继续保留原日志和错误契约，普通 panic 在清理尝试后仍调用原默认诊断钩子。

已考虑保留中毒数据继续运行以及保留托盘但拒绝操作：前者违背采用的规范且状态可信度未知；后者需要额外的启动补偿和命令限制，超出此次聚焦的故障处理改造。用户已确认本决策，实施仍须遵循重构方案的独立子进程测试和隔离验证要求。
